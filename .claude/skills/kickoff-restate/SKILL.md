# 开工复述（动架构的任务 + 长会话新任务）

> 背后的事故：用户写「每个账号一个 workspace」，本意是加个筛选器；AI 按字面规划出一场
> 数据库大手术。另一次：长会话上下文被压缩后凭印象开工，重做了已验证过的事、
> 违反了自己三天前写的设计文档。

## 触发条件（任一满足即执行）

- 任务会改动：数据库表结构 / 架构 / 计费逻辑 / 权限模型
- 当前会话已经很长（上下文可能被压缩过），接到新任务
- 任务来自一句话描述、issue 或口头转述（不是详细 spec）

## 流程

1. **找文档**：先回答三个问题——这件事的设计文档在哪个文件？里面定了哪几条？和现在要做的冲突吗？答不上来就先把文档读一遍。
2. **实测假设**：任务描述里提到的端点、字段、行为，当「待验证假设」——动工前用真实请求 / 真实查询核实一遍（我们遇过 issue 里凭印象写的两个端点，实测一个 404 一个 403）。
3. **交复述**：向用户输出——
   - 「我理解你要做的是：……」（用自己的话，不复读原文）
   - 「我打算改动这几个地方：……」（文件 / 表 / 接口级清单）
   - 「影响面：……」（谁会受影响，哪些行为会变）
4. **等确认**：用户确认理解无误后，才开始写代码。用户指出偏差则修正复述、重新确认。

## 红线

复述没确认之前写的任何代码，都算无效产出。

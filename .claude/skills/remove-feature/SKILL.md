# 删功能前的隐性职责清点

> 背后的事故：砍掉「免费试用金」（看起来只删一行参数），结果用户付款「秒到账」跟着消失——
> 因为即时到账一直是试用金在垫付，真正的套餐额度靠次日定时任务。删掉的是 A，坏掉的是 B。
> 同类错误犯过两次。它专挑「看起来只删一行」的改动下手。

## 触发条件

删除/停用：功能、机制、配置项、字段、定时任务、兜底通路——任何「拿走一个东西」的改动。

## 流程

1. **搜全仓**：用目标的名字（函数名/字段名/配置键）搜索整个项目，列出所有引用点。
2. **列隐性职责清单**，逐项回答：
   - 这个功能明面上的作用是什么？
   - 还有哪些逻辑在**搭它的便车**？（时序掩护、数据垫付、默认值来源、被开关指向……）
   - 每一项便车，删掉之后**由谁接手**？
3. **查开关**：有没有配置开关会切换到这个东西？有开关就必须有实现——删了实现留着开关 = 埋雷。
4. **清单为空也要写明**：「查了哪些地方、为什么确认没有依赖」。
5. **交用户过目**，确认后才删。

## 红线

「改动看起来只有一行」不构成跳过本流程的理由——恰恰相反，这正是本流程针对的场景。
